# Observability and error handling

Ghrouter uses one process-wide structured logger based on Go `log/slog`.
Messages are categorized and carry fields instead of interpolating sensitive
values into prose.

## Levels

- `error`: request/provider/storage/server failures requiring attention.
- `warn`: degraded but recoverable state, fallback, timeout or unavailable CLI.
- `info`: lifecycle, server startup/shutdown and completed provider requests.
- `debug`: discovery decisions, request start and diagnostic details.

## Configuration

```bash
GHR_LOG_LEVEL=debug       # debug, info, warn, error; default: info
GHR_LOG_FORMAT=text      # text or json; default: text
GHR_LOG_COLOR=auto       # auto, always, never; JSON is never colored
GHR_LOG_SOURCE=1         # include source locations
GHR_LOG_FILE=/path/log   # optional 0600 file, instead of stderr
```

Terminal logs are colorized by severity. JSON logs are suitable for shipping
to a collector and remain uncolored. The logger includes `service`,
`category`, `provider`, `model`, duration and lifecycle fields where available.

`GET /metrics` exposes Prometheus text metrics for request totals, fallback
counts, active requests, provider usage/latency, model health, and cooldown
expiry, plus `ghrouter_provider_circuit_open` for provider breaker state. It
exports operational metadata only; prompts, tools, credentials, and API keys
are excluded. The normal ACL middleware protects it when ACL is enabled.

`GET /live` also exposes a routing graph. Its model nodes use semantic states
that the TUI renders as a legend: green `available`, red `unavailable`, blue
`cooldown`, yellow `degraded`, gray `unknown`, and cyan `virtual`. A provider
in `circuit_open` is unavailable for selection until its configured recovery
window; the first recovery request is represented as `half_open`. A green
provider or installed CLI does not override a red or blue model node.

The same live snapshot exposes observed per-model latency samples and P50/P95
values, when requests have completed. The `BRAIN LOG` TUI tab renders only
observed routing decisions, candidate attempts, fallback and status; an empty
request history is rendered as empty rather than synthetic activity. Model
catalog entries also carry evidence-backed classifications for cost, state,
provenance, capability, context and latency.

`GET /health` includes a `health.resource` snapshot for the Brain admission
governor. On macOS, unified-memory pressure is measured from `sysctl` and
`vm_stat`; `observed_at` is populated only after a real sample. A degraded or
emergency resource state can shed auxiliary Brain ranking work so the request
continues through deterministic routing. Metrics that the host sampler does
not support remain `unavailable` rather than being represented as zero.

Successful Chat Completions, Responses, and Anthropic requests also return
redacted routing headers: `X-Ghrouter-Request-ID`,
`X-Ghrouter-Requested-Model`, `X-Ghrouter-Provider`, `X-Ghrouter-Model`,
`X-Ghrouter-Selection-Stage`, `X-Ghrouter-Selection-Reason`, and
`X-Ghrouter-Candidate-Count`. The selection reason is generated by the router
or constrained local brain and never contains the prompt, credentials, tool
arguments, or provider output.

## Error boundary

`internal/observability.Error` separates a stable public message and error code
from the wrapped internal cause. Provider stderr, credentials, prompts and
tool arguments must never be emitted as public errors or log fields. The HTTP
surface returns safe provider failures while the local log keeps the typed
category and timing.

## Current coverage and next work

The CLI lifecycle, HTTP server lifecycle, provider request, provider discovery
and SQLite queue/write failure paths are instrumented. Internal request IDs now
correlate the HTTP request, provider logs and persisted request records without
being forwarded in public provider payloads. Update lifecycle, per-attempt
OpenTelemetry spans, token/cost metrics, audit events and OpenTelemetry export
remain incomplete; see
[`implementation-status.md`](implementation-status.md).
